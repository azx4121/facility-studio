# V5.5.6：新手操作、資料連動與需求清單修訂

本版保留原有工具、公式及進階條件，將第一次使用的流程縮短。舊版發布、提交、授權及歷史驗證保留；本文件不把程式測試當成正式工程設計合格證明。

## 新手先做什麼

只算 NFB、風管、CDA 或照明時，直接選首頁工具，不必建立廠房。完整工作台預設只顯示空調與熱負荷；外氣及室內條件排在空氣線圖前。介面同時顯示已採用的基本參考值與隱藏的自訂條件。

從「開啟練習新案」建立副本，改條件、看結果，再「儲存整案」。「另存新檔」保留方案身分、換儲存位置；「複製為新方案」建立新方案身分並保留來源檔。稽核 JSON、設備分析 JSON 不是可直接編輯的工程專案。

離線教學的必要內容只有六步；空調箱、設備匯入、迴路彙總與其他快算工具是選讀。教學按鈕會開到目前工具，勾選進度只代表已閱讀。

## 問題與修正

| 問題 | 本版行為 |
| --- | --- |
| 新手看到太多分頁 | 工作台按任務顯示；進階資料保留，隱藏不等於停用需求 |
| 不知道預設值是否採用 | 顯示基本參考與來源；被隱藏且改過的條件仍列摘要 |
| 改數字後舊結果看起來仍有效 | 保留上次有效報告、表格及空氣點位，標明待重算，鎖住匯出及回傳 |
| 不知道儲存、另存、複製差異 | 三個動作明確分開；取消不改目前方案或路徑 |
| 重複回傳把需求越加越大 | 相同來源更新；不同來源累加；移除只還原仍由該來源控制的欄位 |
| 多台空調箱回傳互相覆蓋 | 持久儲存需求清單；方案 A/B 是比較，不等於安裝兩台 |
| 夏、冬水量不合理相加 | 同一相容迴路分季節累加，設計流量取兩季較大值 |
| 不同水溫、物性或迴路硬加 | 保留分組；主工作台每一水系統選一相容組，其他組仍在清單與報告可見 |
| 水物性一改就影響全部迴路 | MCHW、CHW、DCCW、PCW、HW 可各自採獨立物性；舊案保留原共同設定 |
| 不同 PF 的電力不能直接合併電流 | 按有功及無功需求彙整，採各盤等效 PF 與設計電流下限；保留原 A/HP 負載的原始 PF |
| 不同供電條件誤併同盤 | 不同電壓或單相設備不直接回傳至三相工作台，須分盤確認 |
| Excel 50% 被當成 0.5% | 辨識數值與百分比儲存格格式，明列原值、格式及採用值；一般格式 0.5 仍是 0.5% |
| 管徑只填壓力、流速缺流量 | 基本流量必填；標準／管內實際流量可互換並保持同一需求 |
| 風管只是定尺寸也要填靜壓 | 預設定寸不需靜壓；啟用已知路徑檢查才顯示並檢核路徑資料 |
| 把盤管目標當成已達成出風 | 空調箱顯示需求目標、已配置容量及缺口；未達容量不當成性能證明 |
| 未知潛熱、加濕、泵浦被當成已確認零 | 未知需求保留待補資料；不以虛構數字代替設備或製程條件 |

## 數值與資料測試

新增測試 `windows/tests/v556_features.py` 及 macOS 對應檔，涵蓋 **54 種不同條件**：Excel 百分比格式、實際 XLSX 匯入、來源更新與移除、多台季節水量、不同迴路／物性分組、舊案移轉、雜湊檢核、單機回傳、混合 PF 與原 A 負載、不同供電拒絕合併、七系統設備回傳、風管定寸及標準／實際氣體流量等。

Windows 來源另通過既有工程、簡易工具、維護與匯入安全測試。兩平台來源各通過 3,803 項雙語一致性檢查，以及教學 20 種條件／85 項檢查。Excel 範本僅更新八格填寫說明，其公式、資料驗證與數值欄位保留。

來源測試在開發主機執行；Windows 及 macOS GUI、內含執行環境、離線運作及交付檔須另外經 GitHub Actions 原生驗收。正式發布由工作流程在兩個原生環境檢核成功後執行，首頁下載只更新至實際發布的版本。可重現的數值見 `windows/evidence/v556-features.json`、`macos/evidence/v556-features.json` 與 `docs/tutorial/verification-*.json`。

## 尚需工程資料

設備表的 PCW 需求若缺供回水溫度，預覽採用值會明列待確認；不得把預覽值當作業主設計條件。氣體管路、DI、真空與排氣回傳提供需求彙整，完整路徑、泵／風機曲線、材質及性能仍須補足。電氣結果為容量、載流量與壓降初估；短路、保護協調、接地、中性線及馬達啟動另核。盤管達成狀態需要原廠選型資料。

## English

V5.5.6 preserves the tools and advanced engineering inputs while focusing the first-use workflow. The workbench shows climate inputs before the chart, adopted references, clear Save as / Duplicate actions, and explicitly stale results with export/transfer locks. The offline tutorial has six required chapters and optional tools.

Demand transfers are keyed by source: repeated returns replace a source, distinct sources aggregate, and removal preserves manual edits. Compatible water circuits aggregate per season and use the larger seasonal total; incompatible circuits remain separate. Water properties can be set per loop. Panel demand combines active/reactive power with an explicit design-current floor, retaining the original PF of current-based loads. Different supplies cannot be silently combined into the three-phase workbench.

Excel percentage formatting is honored and explained, gas standard/actual basis switching preserves demand, and duct sizing alone does not require static pressure. AHU charts describe demand targets with configured capacity and shortfall, rather than proof of actual coil performance. Unknown latent, pump and humidifier demands remain pending.

The new tests cover 54 distinct conditions, with bilingual parity and 20 tutorial conditions checked separately. Native delivery verification is separate from these source tests and is required before publication. Existing releases, history, FY icon, author credit and the noncommercial/internal-use license remain intact.
