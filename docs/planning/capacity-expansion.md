# 現有、擴建與替代方案的容量初篩

這個功能延伸既有 `contributions` 需求彙整與 `design_workflow` 來源快照機制，不取代原有 A／B 比較，也不宣稱完成全套 FEED。適用於團隊先整理工廠、辦公室或擴建的公用系統需求與供應缺口。

## 操作

1. 在完整工程工作台選「容量／擴建規劃」。計畫獨立另存，不會改寫主案或已帶入負荷。視窗重開會重用尚未關閉的計畫；關閉工作台會先保護未存容量草稿。
2. 新增需求列，分為 `current` 現有或 `expansion` 擴建。填系統、實體來源 ID、供應邊界、單台各工況需求、台數、同時率及來源已含裕度。數字空白是未知，明填 0 才是已知零。每筆需求另有「已核對為完整需求，非僅已知小計」確認，新增／擷取預設未確認；未確認的數字只保留為已知小計，不產生完整需求、餘量或缺口。
3. 新增供應列，填相同邊界與額定工況下的單台容量、台數、降額係數、來源文件及版次。電力為有功 kW，不能把 kVA 或製程熱負荷當成耗電；水量用 LPM，排氣為指定實際溫壓下的 CMH。
4. 各系統的條件必須完全一致才可相抵。不同盤／迴路、電壓／頻率、冷水介質與供回水、排氣種類／溫壓／靜壓會分列，缺值不會算成通過。
5. 額外裕度在每一個同時工況合計後只套用一次。已含在來源數值內的裕度保留並另註，不能再套相同的來源裕度；額外裕度必須有理由。已含同時率的整組來源值應設台數 1、同時率 1。
6. 未建方案時評估全部列。有替代設計時，在需求頁選取該方案所有現有與擴建列，再到供應頁選供應列，到結果頁選「將兩頁選取列記為方案」。方案互為替代，永不相加。同方案不能重複計入同一系統／實體 ID。
7. 勾選範圍、完整清單及 N−1 供應假設確認後重算。這是使用者確認，不是驗證身分或工程簽核。修改範圍／裕度、需求或供應列、替代方案後，介面會清除原先的整案確認，必須重新核對；只改計畫名稱不影響確認。匯出會重新計算並核對目前主案，無法核對或已改變的擷取快照只能列為待覆核。

## 從需求彙整擷取

「從需求彙整擷取」複製已明確納入的電力、CHW、PCW 與排氣來源一次，保留來源指紋、待辦及季節數值。**不再加上已包含這些來源的主案總量**，也不自動把其他既有基數推成完整廠區需求。未提供的頻率、介質名稱、排氣額定工況、容量等仍為未知，清單完整性預設未確認。

擷取是來源快照，不是同步編輯。主案、需求彙整或空調箱原始資料一旦變更，舊快照失效。重新擷取是建立新的容量計畫，會先詢問未儲存變更；請先另存既有人工輸入。修改擷取數值會留下人工修改註記，需補新的來源文件／版次與覆核。所有擷取列都須另行確認需求完整性；刪除待辦或更改文件版次不會自動完成此確認，避免把未知泵浦等遺漏組件當成零負荷。

報告中的計畫 SHA256 是經驗證、正規化的採用條件指紋，不是 JSON 原檔的位元組雜湊；整數／小數形式的額外裕度會正規化為同一數值。

計畫格式為 version 2。開啟舊版 version 1 時保留原始數字與待辦，需求完整性一律改為未確認，另行覆核後才能使用完整需求餘量。待辦已達上限時不刪除既有記錄，結果仍會明示完整性未確認。

## 數學與範圍

- 各工況需求 = Σ（單台值 × 台數 × 同時率）；設計需求 = 此合計 ×（1 + 額外裕度）。先加總同時工況再取峰值，不能把各設備不同時間的峰值相加。
- 正常供應 = Σ（單台額定 × 台數 × 降額）。N−1 = 正常供應 − 最大單台降額容量，不是扣掉最大整組。
- 餘量 = 供應 − 設計需求；缺口 = max(0, −餘量)。缺資料時餘量／缺口保持未知，已知小計另列。
- 水側等效 kW = LPM ÷ 60000 × 密度 kg/m³ × 比熱 kJ/(kg·K) × 溫差 K。這是同一水量的另一種表示，不另加一筆需求。
- N−1 是比較情境，是否為本案必要條件由業主／設計者決定，並非軟體預設的法規要求。本版正常與 N−1 一併列示，CLI 退出碼 0 要求兩者皆足夠，尚無僅核對正常情境的獨立模式。
- N−1 假設剩餘機組可同時向該邊界供應。不包括共因失效、母線／閥件／管路瓶頸、備用機啟動或轉供時間。未建立此能力時不能用數字表宣稱備援合格。
- 未做 kVA／無功與啟動、短路／保護協調、泵／風機完整曲線、管網揚程與支路瓶頸、現場負荷量測或工程師核准。

## 合成例與命令列

`python tools/verify_capacity_planning.py --platform windows --output evidence/capacity` 產生四個明確標記為合成資料的計畫、報告與獨立算式。macOS 原始碼可改為 `--platform macos`，不是在本機實際執行 macOS App 的意思。

- 電力：現有 100 + 擴建 60 kW，額外 10% → 176 kW；3 台 × 100 kW × 0.9 → 正常 270、N−1 180 kW。
- CHW：兩個同時工況合計 160／150 LPM，峰值 160，不是分別峰值相加的 200。
- PCW：4 台 × 80 LPM × 0.75 → 240 LPM；ρ=1000、cp=4.1868、ΔT=5 K → 83.736 kW，沒有重複加算。
- 排氣：同一實際溫壓與靜壓下，1000 + 600 CMH 加 10% → 1760 CMH。

在已有原始碼環境下，`python -c "from facility_studio.cli import main; raise SystemExit(main())" --capacity-plan plan.json --report report.txt --result result.json` 可重現初篩。綁定主案的計畫另外給 `--capacity-workspace current-workspace.json`，不提供時保持來源未核對。

退出碼 0 只代表已列方案正常及 N−1 的數值初篩皆足夠；3 表示待資料、待覆核或不足；2 表示檔案／輸入錯誤。這些退出碼都不是完整 FEED、法規或真實專案驗收。
