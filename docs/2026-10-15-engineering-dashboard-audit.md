# 工程模型與儀表板修訂審核

本次來源修訂於 **2026-10-15（台灣時間）**整理，基於 V5.6.0 的 `ac8a9757`。這是可檢視、可執行的原始碼修訂，並非已重新封裝／發布的 EXE 或 DMG。專案資料結構由 schema 11 移轉至 12，保留既有輸入及草稿。

## 對原修正建議的判斷

| 主張 | 真實原始碼與本次處理 |
| --- | --- |
| FFU 一律應加 OA | 必須先定義氣流路徑與 ACH。原程式的 FFU／DCC 共用 `circ` 可描述獨立循環，卻不足以描述 MAU 進入 FFU 上游靜壓箱。新增兩個明確選項，舊案保留獨立循環。 |
| 單台 AHU 有 FCU 必填彈窗 | 目前 `ahu_engine.py` 是分段 MAU 模型，沒有該 `sys_mode`／`fcu_cmh` 驗證。真正的 UI 問題在主工作台：進階模式顯示架構互斥的停用 FCU／RCU 欄位，已修正。 |
| 既有零壓差洩漏仍有 0.5 ACH | 描述的公式不存在於目前版本。主案原有門縫孔口法在零壓差已歸零；保留此法，另提供可選的 15 Pa 基準 ACH 初估，不將兩種方法相加。原主案也已有人員外氣量下限。 |
| 主案缺少 FFU 發熱及室內潛熱 | 主案原有 `ffu_count * ffu_w`，並以 `ws = room['w'] - moist / m` 將室內產濕納入 MAU；不重複加計。只有選擇新混合路徑後，FFU 台數改變所增加的發熱需重新計入。 |
| 快算熱負荷與泵浦公式有錯 | 目前快算原本沒有這兩個工具。本次新增，明確分離熱量、機械軸功率與電氣輸入功率。 |
| 電流一律再除效率、斷路器一律乘 1.25 即合規 | 電氣輸入 kW 採 η=1；軸輸出 kW 才除馬達效率，避免效率除兩次。1.25 倍只是連續負載初估，不能替代馬達啟動、短路與保護協調。既有 HP 換算及最大馬達加成邏輯保留。 |
| 矩形風管必須全部改成 Huebscher | 原有實際矩形風速搭配水力直徑 Dh 是一致模型，並非單憑沒用 De 就錯。新增可選等摩擦圓管法，De 必須搭配等效圓管風速；局部損失仍使用實際構件風速壓。 |
| 需要跨工具連動與醒目總覽 | 成立。新增明確帶入、上游修改後的失效提示、七項設備總覽、HTML5 卡片與結構表，保留原報告章節及驗收字串。 |

## 氣流路徑與 ACH：三個可驗算情境

`C` 為區域 ACH／截面法得到的基準風量；`O = oa_room_cmh` 為完成通風、排氣、正壓及除濕需求後的最終外氣量。以下風量均以室內狀態基準比較，不能混用 MAU 外氣進口的實際體積流量。

| 氣流路徑 | ACH／截面風量定義 | FFU 總風量 | DCC 回風量（沿用循環模式） |
| --- | --- | --- | --- |
| 獨立 FFU 循環，MAU 直接入室 | 原案循環風量 | C | C |
| MAU 入靜壓箱後經 FFU | 室內基本循環，不含 OA | C + O | C |
| MAU 入靜壓箱後經 FFU | FFU 總送風，已含 OA | C | C − O |

儲存欄位為 `ffu_topology`、`ffu_airflow_basis`；預設及 schema 11 舊案移轉採第一列。`circulation_cmh` 保留原案基準量，新增 `ffu_total_cmh`、`dcc_return_cmh`、`dcc_cmh`、`dcc_design_cmh`，避免同一欄位兼作兩種設備風量。

選擇「獨立 DCC 循環」時，`dcc_cmh` 採明填的 DCC 自有循環量，不能把它當成全部 FFU 回風必然穿過 DCC。若實際設計是所有回風均穿過 DCC 的串聯路徑，應選沿用循環模式；自有循環／旁通設計須由實際氣流路徑確認。

FFU 台數在最終 OA 確定後向上取整，隨後更新風機入室發熱、室內顯熱及 DCC 剩餘負荷。原模型以產濕量及可達 ADP 解析求 OA；FFU 的顯熱不改變該除濕質量流量，因此不加入無必要的迭代。DCC 品質檢核使用 `dcc_design_cmh` 與夏冬較大需求，保留季節標記。

若總送風小於外氣，負的回風需求會保留並標為不可行，不截零偽裝成有效設計。FFU 1200×600／1200×1200 為名義模組；真正 4 英呎為 1219.2 mm，安裝尺寸仍依型錄。85% 是可調專案配置警戒值，並非 ISO 14644-4 的通用上限。

## 熱濕平衡、設備選型與資料帶入

- **主案熱濕平衡：**保留原 MAU 除濕、再熱、MAU 入室顯熱與 DCC 分工。主機冷量由實際水側盤管負荷加總，不將完整人員潛熱再加一次。不同溫度的 MCHW／CHW／DCCW 分列，不假稱為共同主管。
- **熱負荷快算：**「外氣至室內基準」可將室內顯熱、人員潛熱及外氣到室內焓差相加；「實際露點送風」不重加已交由 MAU 處理的人員潛熱，另以明填的 MAU 入室顯熱抵扣 DCC。抵扣受風量與明填送風溫差限制；未抵扣時僅為容量上界。這個快算不證明濕度可達性，詳細選型使用完整工作台。
- **漏氣與 OA：**基準 ACH 法為 `V * base_leak_ach * sqrt(ΔP / 15)`，ΔP≤0 時正壓外洩為零；它不代表負壓沒有滲入。15 Pa、1 ACH、30 CMH/人及外氣焓差 50 kJ/kg 均為可調初估條件，不宣稱是普遍法規值。
- **泵浦：**清水水功率 Q(m³/h)×H×9.81/3600；軸功率除泵效率；輸入電功率再除馬達效率。馬達銘牌 kW 是額定機械輸出，以軸功率×1.15 向上選級；超過內建 75 kW 級距顯示需另選。閉式循環不直接加建築樓高，設備壓降、末端及靜揚程分別明填。
- **電氣：**快算可另列 1.25 倍連續負載電流與標準 AT 初估，超過 400 A 不硬夾。總有效功率只彙整明列設備輸入，冰機須提供 COP 或實際輸入功率。來源重複會拒絕，MAU、製程與冰機缺項分別提示。UP／NP 的 AT 不可相加冒充主進線 MCCB。
- **連動：**潔淨室→熱負荷→冷熱水→泵浦→電力使用「帶入上游結果」。上游修改後，連結下游結果失效並阻止匯出，直到重新帶入或明確改回手動輸入。不得以熱負荷 kW 代替設備用電 kW。

## 介面與報告

快算及單台 MAU 使用統一工業色票、中文標籤與等寬數值、左側可捲動三欄表單、右側 KPI／斑馬紋明細表及行內錯誤橫幅。Enter 可計算；長選項另顯示完整提示。Windows 啟動在建立 Tk 前設定 DPI awareness；macOS 保留平台捲動、字型、Command 快捷鍵與原生退出處理。

SCADA 使用原生 Canvas 向量，隨尺寸重新排版：OA 綠、冷卻青藍、加熱橘、送風／FFU 亮藍、EA 琥珀。單台 MAU 沒有室內／回風來源時，明示未提供，不製造讀值。

TXT 的第一章之前新增七項設備總覽；原 `室內顯熱 ... kW` 等段落保留。HTML 提供頂部 KPI、需求與選型欄、狀態標記、列印樣式及動態內容跳脫。主案不完整時仍拒絕完整報告；單項／連動總覽將未計算設備明列缺值。

- [美國能源部泵浦系統指南](https://www.energy.gov/sites/default/files/2014/05/f16/pump.pdf)：泵浦效率與功率邊界。
