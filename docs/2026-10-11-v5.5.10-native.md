## 先前失敗通知與修正

第一輪 [Windows run 38109907960](https://github.com/azx4121/facility-studio/actions/runs/38109907960) 有五項焦點判定失敗，發布被擋下。補上版面事件等候與診斷後，[run 38110579672](https://github.com/azx4121/facility-studio/actions/runs/38110579672) 在 Server 2022 三次均通過，但 Server 2025 英文電力欄位仍有一項失敗；診斷顯示目標 `mapped=0`、焦點在根視窗，測試沒有先將保留捲動位置的欄位帶入可視區。

Windows 測試現在先處理版面事件、用既有 `ScrollPage.reveal()` 捲至目標，再要求焦點及投遞按鍵。原有可輸入、焦點、單次字元、實際計算與報告鎖定判定均保留，沒有略過失敗檢查。最終 run 38111338133 的兩個 Windows 環境、六次執行全部通過。上述兩次失敗均沒有發布 EXE；舊的失敗紀錄仍保留。
