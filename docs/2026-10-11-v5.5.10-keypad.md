# V5.5.10 數字鍵盤小數點修正

獨立數字鍵盤的「.／Del」可能由系統送成 `Delete`，而非 `KP_Decimal`。V5.5.9 只接 `VK_DECIMAL=110` 與部分小數點 keysym，漏接 Windows 非 extended 的 `VK_DELETE=46` 及 `KP_Delete`。用上一版原處理函式重現這些事件時，輸入 `12` 後按鍵仍為 `12`，没有插入小數點。這是來源事件重現；尚不能推定使用者實體鍵盤的 Num Lock／驅動條件。

修正內容：

- Windows 以 Tk 傳遞的 extended-key 位元分辨專用 Delete 與數字鍵盤 Del；數字鍵盤兩種事件均插入單一 `.`，一般 Delete 保留刪除功能。
- 支援 `KP_Delete`／`KP_Separator` 等事件；主鍵盤句點維持原生行為。
- 選取部分文字時先定位選取起點，再替換成小數點。
- 同時檢查 ttk 的 disabled／readonly state，保留 Ctrl／Alt／Command 編輯快捷鍵。
- 新視窗及重新開啟視窗都掛接輸入處理，避免重複綁定。

Num Lock 關閉而送出可識別的數字鍵盤 Del 時，本程式將這顆鍵作為小數點輸入；要刪除可使用專用 Delete 或 Backspace。Windows 不具 extended-key 資料的模糊事件不會僅憑 `Delete` 名稱被改成小數點。未修改工程公式、輸入合法範圍、作者署名或授權；macOS 的原生 UI 實作保留。

## 驗證範圍

兩套來源各 64 項鍵盤處理檢查通過，包含事件辨識、實際插入、部分選取、一般 Delete、Num Lock 相關狀態、停用／唯讀及快捷鍵。既有 regression、v55、v552、simple、v554、v556、v557、v558、v559、maintenance、security、bilingual、tutorial、use-case 檢查全部通過；發布維護 31 項、Python 語法及 76 個 installer payload hash 通過。[來源證據](evidence/v5510-keypad-source.json) 保留執行輸出及上一版處理函式的失敗重現。

本次沒有重跑 V5.5.9 的 100 組無塵室壓力測試；該次結果保留於[前次紀錄](2026-10-11-v5.5.9-resilience.md)。本次是輸入事件修正，工程運算模組未變更。

原生 GUI 檢查已加入 EXE／App 的 self-test：七種簡易工具的雙語實際小數輸入與計算、主鍵盤句點、專用 Delete、選取替換、停用／唯讀、未完成草稿與匯出鎖定、完整工作台、單機空調箱、工程快算及新視窗。Windows 另以 `PostMessageW` 投遞 `WM_KEYDOWN`／`WM_KEYUP`，比較未掛接修正時與修正後的數字鍵盤 Del，並驗證 extended Delete。

原生建置／GUI／公開發布目前待 Actions 完成。來源測試使用 Linux，不將它列作 Windows 或 macOS 原生驗收；原生事件測試也不等同實體鍵盤、輸入法或驅動驗收。公開 EXE／DMG 確實發布後才更新首頁下載連結。

Windows 事件位元依 Tk 自身的 `EXTENDED_MASK`／`GetState()` 使用：
[Tk generic/tkInt.h](https://github.com/tcltk/tk/blob/core-8-6-branch/generic/tkInt.h)、[Tk win/tkWinX.c](https://github.com/tcltk/tk/blob/core-8-6-branch/win/tkWinX.c)。未安裝全域鍵盤 hook，也未改系統 Num Lock 或鍵盤配置。
