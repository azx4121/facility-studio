# 5.7.3 正式驗收證據格式 / Formal acceptance evidence schema

此頁是空白證據格式與判定規則，不是驗收通過或未通過的狀態公告。每次交付的實際結果放在對應 commit 的 CI 紀錄及 Release 附件；不為回填狀態修改已凍結的來源或隨包文件。只有對應 Release 已提供該平台成品、SHA256 與匹配的驗收證據時，該平台下載才有效。

This is a blank evidence schema, not a pass/fail announcement. Actual results belong in CI records and Release attachments for the exact source commit. Do not rewrite frozen source or packaged manuals to backfill status. A platform download is valid only when the matching Release provides its artifact, SHA256 and matching acceptance evidence.

| Evidence field | Required content in the matching CI/Release evidence |
| --- | --- |
| Exact source identity | Full final commit/tree; complete build-input manifest and digest; formal version/channel/build |
| Source regression / engineering / bilingual / security | Results for the exact formal source, both platforms in separate processes; command/check counts, failures/skips and nonzero failure behavior |
| Windows native | Identical installer/portable on Windows Server 2022 and 2025; external-Python independence, offline hook, real win32 geometry and install/uninstall preservation; exact hosts and artifact hashes |
| Mac native | Apple Silicon ARM64 ZIP; runtime, aqua GUI/menus/languages/save/tutorial/licenses and deep/strict codesign integrity; exact host/architecture and artifact hash |
| Negative acceptance gates | Wrong-version/suite/manifest/source-mode/missing-check rejection results |
| Signatures / notarization | Actual per-artifact verification output; distinguish unsigned/ad-hoc integrity from trusted Windows publisher or Mac Developer ID/notarization; missing evidence is not verification |
| Release / assets | Tag/commit, per-platform asset names/sizes/SHA256, CI run links, public download readback and hash comparison |
| Outcome / exceptions | Explicit per-platform pass/fail/unverified and unresolved blockers; no skipped required check counted as a pass |

Do not fill a gate from preview or historical release evidence. Each record must identify source manifest, suite/check set, actual host/architecture, Python/Tcl/Tk, job links and final package hashes. If only one platform completes, state that scope and leave the other explicitly unverified. A matching version string alone is not sufficient.

發布前完成最終來源與原生成品驗收；發布後回讀 tag／Release／資產並下載核對 SHA256。此格式不代替實測紀錄，不保證未測 OS、硬體或企業政策。簽章或其他操作若改變成品 bytes，須對新 bytes 重驗並產生新雜湊。

## 來源防護 / Source protections

Three legacy workflows (`windows-offline-release.yml`, `macos-native-release.yml`, `public-downloads-maintenance.yml`) have no push trigger and fail manual runs with exit 1. Both old publisher scripts fail without network actions. This retires obsolete release/cleanup paths; it is not native acceptance or proof of publication.
