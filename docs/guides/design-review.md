# 設計依據與交付審查｜5.7.3

[English](design-review.en.md) · [工具指南](README.md) · [發布狀態](../verification/5.7.3-release-acceptance.md)

本頁為 5.7.3 版本指南；原生驗收與發布狀態以對應 commit 的 CI 紀錄及 Release 附件為準，本指南不宣稱已通過。本流程協助已列 FEED 範圍內的文件準備，不認證工程合格。

1. 在主畫面開「設計依據與交付審查」，新增獨立專案。填專案／版次、廠址、業主、系統範圍與界面、工況／最不利條件、單位與基準、驗收準則／容許誤差及編製者。
2. 每行規範填五欄：**名稱｜版次｜條號｜適用範圍｜來源**。採可追溯且適用本案的依據，不以空泛「符合規範」替代。
3. 核對交付清單：設計依據、平衡／需求、流程與界面、設備規格、管路材料、電力保護、控制、配置、風險及數量／成本等。誠實標明範圍與缺件；軟體不自動完成全部工程交付物。
4. 明確附加相關文件。附件是附加當下的快照，不是即時同步；來源改版需重新附加並覆核。移機請複製整個資料夾與 evidence 子資料夾。
5. 覆核者須與編製者不同。程式只檢查填寫名字與紀錄有效性，不驗真人身分、資格或數位簽章。設計依據、交付清單或證據改動會讓舊覆核失效。
6. 儲存與匯出建立新檔，保留前版並閱讀待辦／未達項。「文件齊備，可送工程審查」只代表所填證據與覆核紀錄齊備，不代表 FEED、法規或設備性能認證。

仍須由專案團隊以同工況原廠資料、完整交付範圍及專業覆核確認。公開問題回報請用合成資料，不附業主機密文件。
