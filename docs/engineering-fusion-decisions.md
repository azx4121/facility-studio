# 五庫核心融合：實作邊界與稽核查證

本輪目標為 PsychroLib、python-hvac、fluids、CoolProp、Pint 實際參與既有計算、選型、單位與報表；不以套件已安裝或只增加獨立檢核頁視為完成。
基準為 eaab767e92cbb6731e7695f59a49ca7b74ca1f23。原工作樹、正式 App、已驗收包保留；本分支不合併 main。

## 基準版本盤點（eaab767，非本輪完成狀態）

- python-hvac 官方目前 HEAD 為 94247560a667905bfbf67e45a58965a58254fce8，專案宣告 Python >=3.11,<3.13。整合環境採共同支援的 Python 3.12.16。
- python-hvac 的 HumidAir／Fluid 封裝 CoolProp，不能稱為第三種獨立物性模型；其盤管 ε-NTU 與翅片管模型具有不同的產品功能價值。
- eaab 的純水使用 `PropsSI(..., "Water")`，為 HEOS／IAPWS-95；稽核稱其為 IF97 不正確。
- 原工程核心 engine、ahu_engine、utils、winter 在 eaab 與公開基準2c7f37c一致，稽核將部分原有盤管／冬季功能稱為5.6.1新增，版本歸屬須更正。
- ahu_engine 的 active_installed_electric_kw 目前未列入水洗泵輸入功率；須檢查單機及帳本的同一計量邊界。
- 目前 python-hvac 只有隔離參考案例，尚未隨產品執行；fluids／Pint 的主要使用點在檢核中心，尚未全面接入舊流程。

## 不直接採信的稽核結論

- 「FEED能力65%～70%」未附完整交付範圍、分母及驗收矩陣，不能作為認證或完成率。
- EIGA Doc13/20 曲線使用絕對壓力、區分撞擊／非撞擊位置及材料條件；不是文中所稱15～30bar(g)一律降為3～4.5m/s。
- SiH4等氣體的6m/s等數值未附可查證規範條款，不列為通用安全上限。
- 冷量不能在未定義冷源拓樸及需求邊界時直接相加，避免主／次側或既有負荷重複計算。
- 泵浦電功率不等同100%進入空氣的熱量；水洗器的熱分配需有控制體、熱源與水側條件。
- `winter_ffu_ratio`等房間／FFU參數不應無差別加入不含FFU的單機AHU模型。

官方氧氣文件：https://www.eiga.eu/uploads/documents/DOC013.pdf，§4.4、Figures2/3。

## 本輪實作原則

1. 中央化單位及物性服務；既有輸入、選型、報表直接使用，保留顯式自訂物性與模型適用範圍。
2. PsychroLib參與既有濕空氣狀態；獨立驗證改用不同模型／解析基準，避免自我比較。
3. CoolProp提供明確溫壓、流體與後端下的物性；未知條件不得默認為已確認。
4. fluids參與水路摩擦及具適用條件的氣體壓降；參考 https://fluids.readthedocs.io/fluids.compressible.html 。
5. Pint處理既有單位流程，區分絕對溫度、溫差、表壓／絕壓及不同冷凍噸定義。
6. python-hvac加入可操作的盤管／空調過程功能，採其獨特模型，不重複包裝CoolProp充當獨立證據。
7. 工程警戒值與規範來源分別記錄；未知或專案未核定資料不得顯示為已符合FEED。
8. 先驗證新Python環境的既有回歸，再逐項改造、測試與打包；只交付通過實測的新版本。

## 本輪產品變更

- 主案與單機盤管改用 python-hvac 熱質平衡，明列凝結水帶出焓。建立不完整過程後再填熱濕端點，避免其建構子額外自動外插 ADP 產生無關負含濕量警告。
- PsychroLib 飽和壓、焓與比容進入既有核心。零／極低含濕量不被套件 1e-7 下限改寫；比容沿用專案明列的 0.621945 分子量比，修正庫的倒數捨入係數，保留舊案風量。
- fluids Colebrook 摩擦因子進入主案與快算；專案自訂實際內徑與過渡區規則保留。水路可選流速＋摩擦梯度聯合選型，超限接入品質閘門、畫面與報告。
- CoolProp 純水物性可在主案每一迴路及既有冷熱水快算選取，要求明填溫度／絕壓。來源帳本不能靜默覆寫自動物性下的水量；需先選手動物性再採用來源整組介質。
- Pint 共用 python-hvac 的單位登錄庫，接入原單位工具及風水量表單換算。保留美制冷凍噸、IT BTU、日本冷凍噸、壓頭參考、PF及效率等既有明列定義。溢位仍拋結構化 ValidationError，GUI不崩潰。
- 工程模型設定在主工作台提供「空調與冬季／水路物性與選管／NP設備用電」三分頁。五項進階參數可操作，舊專案原值保留。
- AHU 新增可填幾何的 C2 ε-NTU 核對，冷量、乾球與含濕比須同時檢核，不將需求點冒充設備出風。水洗泵總電力納入裝機功率，入空氣熱依明填比例，未知時保留待資料。
- Chiller 分列內建同時峰值／水路容量包絡，可明確選擇獨立冷源包絡模式，避免餘裕重乘及主次側重複。NP 可連動已知本案設備，明列馬達效率、FFU電氣輸入、再熱熱源、加濕器功率及冰機邊界；既有帳本NP來源阻擋重複加總。
- 再熱選電熱時不再同時計入HW需求；冬季明確指定的末端HW需求獨立保留。來源不明的用電與設備阻力不當成已確認的零。
- 使用各自獨立的5.7.0安裝、資料與版本名稱；不修改正式App、main、Hub或舊交付資料。預設繁體中文。

## 封裝實測發現與取捨

- 第一輪凍結執行抓出 IAPWS VERSION 資源遺漏，新增收集 iapws 資料。
- 第二輪證明 python-hvac 經 hvac.charts 匯入 CoolProp.Plots；不能照外部稽核一律排除 Plots。保留實際必要模組，排除未用的 CoolProp.tests／GUI。
- macOS libobjc 僅在 macOS 實例化，Windows不載入。原稽核稱頂層無條件載入不正確。
- 封裝成功不等於可執行：交付檔須再執行融合驗收、既有GUI驗收及離線網路攔截。

## 測試調整的依據

原airflow測試的數值門檻保留；MAU最後位浮點值改用1e-12相對誤差，設備台數仍完全相同。新增摩擦壓損品質項目會合法改變舊案例狀態，狀態比對只容許該新項目造成的變動；提供完整資料的案例改選雙條件選管。冬季HW測試由「拒絕熱源欄位」改為驗證顯式熱源確實計入HW且守恆。歷史5.6功能驗收的版本標籤改為5.7.0，其餘功能檢核保留。原有雙語測試新增字典；僅診斷用合成案例名稱與其他診斷模組一樣不當作產品翻譯字串。
