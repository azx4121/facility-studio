# 照明報告第一階段：可追溯的 FEED 初估

## 需求與參考

使用者希望照明工具能產出類似「作業廠房(全).pdf」的工程報表。參考文件是 DIALux 4.12 的七頁輸出：燈具資料、空間摘要／等照度圖、燈具表，以及各表面直接／間接／總照度和均勻度。第一階段借用資料分區，不複製品牌、公司資料、配光圖或數值結果。

參考兩案例間接反射占工作面平均照度約四成。單憑平均照度、兩條配光截面與 PDF 圖面不能重建完整光度資料、逐盞座標或 32×32 網格；不能調整 U 硬湊成參考照度。

## 本次實作

- 保留既有 Eavg=N×Φ×U×M/A 與向上取整邏輯，未新增物理模型。
- 新增五個選填來源／識別欄位，隨成功結果保留。輸出不採用呼叫者後來提供的不一致草稿；未知的舊結果不補造輸入。
- 只有長×寬模式保留實際 L/W；體積模式只保留用於面積換算的淨高；K 模式才採用安裝／工作面高度。
- `lighting_report.py` 提供共享報告資料與區塊；TXT、專用 HTML、跨模組 HTML 共用。HTML 以 A4 直式列印，照明匯出預設 HTML；其餘工具匯出預設不變。
- 報表包含來源、計算條件、表面摘要、單一燈型明細、完整燈具總流明、總功率、功率密度及每 100 lx 功率密度。燈具流明與光源流明分欄，未有光源資料就標示未提供。
- 欠缺的最小／最大照度、均勻度、各表面結果、光度網格、反射與 UGR 明示未計算，結構化結果使用 None，沒有假裝成零。
- 使用者文字透過既有 verbatim 機制保留原文；完整 HTML 翻譯階段執行 escape。沒有新增可執行使用者 HTML。

## 邊界與下一階段

這是單空間、單一燈型的平均照度報告，不是多燈型配置工具，也沒有平面配置或等照度圖。PDF 由使用者瀏覽器列印功能產生，沒有直接 PDF 生成引擎。

下一階段應另定有版本的光度資料／場景／網格結果結構，輸入真實 IES/LDT、燈位 x/y/z、朝向與傾角、工作面網格、邊界，再從逐點 lx 計算統計及等照度圖。直接光必須明示不含反射。若匯入第三方網格，需保存來源及方法，不把外來摘要當成原生計算。反射模型和 UGR 另做獨立驗證。

## 交付與驗證界線

Windows 與 macOS 的共享原始碼同步。`windows/installer/payload` 與其雜湊清單屬於既有追蹤安裝檔的驗證輸入，本次保持原樣；新的候選安裝版須由現行建置流程另建，不能僅改歷史 payload 並宣稱安裝檔更新。

本次新增 `tests/lighting_reports.py` 覆蓋：原公式結果、取整後照度正規化、零照度、零瓦但有型錄流明、未知值、隱藏幾何草稿、結果快照、雙語、惡意 HTML 文字、舊結果、跨模組報告、匯出取消／重複／對話框中變更。此套件的匯出流程採顯示層 stub，不是原生 GUI 驗收。

在雲端環境跑既有數值、報告與雙語回歸；原生 Windows/macOS GUI、安裝版，以及實際瀏覽器 A4 列印版面仍須候選版驗收。雲端 Chromium 因 Unix socket 限制無法啟動，因此不可將 HTML 內容檢核宣稱為目視 PDF 驗證。
