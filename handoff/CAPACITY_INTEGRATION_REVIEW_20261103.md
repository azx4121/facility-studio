## 可使用的來源功能

- 電力有功 kW、CHW／PCW LPM、指定實際工況排氣 CMH 的現況、擴建及替代方案。
- 先加總相同同時工況，再比較各工況峰值；不把不同設備在不同時間的尖峰直接相加，也不把替代方案相加。
- 正常容量與扣除最大單台降額容量的 N−1 算術，分列需求、餘量、缺口。不同供應邊界、電壓／頻率、水側條件、排氣種類／溫壓／靜壓不得互抵。
- 水量等效 kW 只作同一需求的另一種表示，不重加成新負荷，不轉為電氣輸入。
- 保留需求帳本來源與主案快照，排除已含來源的主案總數，禁止重複實體來源。人工修改保留原始追溯並要求新依據；主案／AHU 變更失效舊預覽，報告匯出重新核對。
- 獨立計畫 JSON、文字報告、CLI、可編輯視窗及未存草稿保護，不覆寫主案需求。

## 覆核發現與修正

1. **空白邊界不能通過。** JSON 的空格或全形空白邊界原先可被當作已知值；現在仍列待資料，不能宣稱容量足夠。
2. **超大整數正常拒絕。** 先檢查數值範圍再做有限數檢查。合法 JSON 的極大整數回報輸入錯誤與 CLI 退出碼 2，不再產生未捕捉的 OverflowError。
3. **完整需求與已知小計明確分開。** 新增每筆需求的 `demand_complete` 獨立確認，預設為 false。所有帳本擷取也預設未確認，因原帳本的待辦文字混合缺漏組件與其他注意事項，不能用關鍵字猜測完整性。刪除待辦、修改版次或勾選整案範圍不會自動確認每筆完整需求。
4. **保守移轉。** 計畫格式升為 version 2；舊 version 1 保留數字、來源與全部待辦，但需求完整性仍未確認。100 筆待辦已滿時不刪除既有記錄，報告另會指出未確認完整性。
5. **報告及介面保留使用者原文。** 來源 ID、名稱、邊界、使用者待辦與主案識別不因切換英文被改寫；來源原文可保留中文。視窗標題加入語言切換，列編輯器有獨立完整性確認。
6. **較完整的草稿護鎖。** 可見輸入變更立即清除快取結果；開啟計畫的對話框期間若發生新編輯，重新確認是否捨棄，不沿用對話框前的同意。原有存檔／匯出對話框後重新核對與原子寫入保留。範圍、裕度、來源列或方案變更會清除先前整案確認，避免把前一版的確認套用到新條件。

### 缺漏泵浦的實際運算鏈

合成輸入經真實 AHU 引擎、帳本轉換及容量擷取：兩台風機各 5.5 kW，水洗泵耗電未知。修正後保留 **11 kW 已知小計**；完整需求、正常／N−1 餘量及缺口均為未知。另列的三台 100 kW 供應仍可計出正常 300、N−1 200 kW，但不宣稱能滿足未知完整負荷。這是使用產品真實程式路徑的合成測試，不是真實廠房的量測或驗收。

## 適用限制與尚未完成

- 本版 CLI 的退出碼 0 同時要求正常與 N−1 初篩足夠，尚無僅核對正常情境的獨立模式。確認勾選只是使用者陳述，不是工程簽核。
